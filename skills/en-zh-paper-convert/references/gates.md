# 门控口径与失败定位（gates）

> 门控是**交付前置条件**：任何一项 FAIL → **不得放行**，回到修复步骤。
> 门控 PASS **不等于**正确 → 仍需目视抽验（见 §6）。

## 1. 门控清单

| # | 项 | 判据 | 口径说明 |
|---|---|---|---|
| **G1** | LaTeX 错误 | 编译日志中 `^!` 计数 = **0** | 只看**最终一遍**日志（前面的未定义引用是正常的） |
| **G2** | 缺字形 | `Missing character` 计数 = **0** | 缺字形 = 页面印出空白或错误符号 |
| **G3** | 越栏 | `Overfull \hbox` **最大**值 > **8pt** → FAIL；`\vbox` > **120pt** 才 FAIL | **必须全量取 max** |
| **G4** | 图表编号闭合 | 期望图号/表号**无缺失**（**子集判定**） | 见 §4 |
| **G5** | 译者痕迹 | 交付 PDF 文本层中 译注/翻译说明/自查/进度标记 = **0** | 见 §5 |
| **G6** | 页面几何 | 实际页面尺寸 ≈ 台账纸张（±3pt） | 超差先查单位（`pt` vs `bp`） |
| **G7** | 字体嵌入 | 所有字体 `embedded = yes` | 检查 `uni` 列而非 `emb` 列的口径差异 |
| **G8** | 门控日志可用性 | 日志**读不到 → FAIL**（`gate-log-unreadable`） | **不得默认 0** |
| **G9** | 构建日期泄漏 | 交付件不得含**编译当天日期** | 见 §1.3 |
| **G10** | 矢量表未使用 | `tables.json` 有 `ok` 记录却**未走矢量嵌入** → FAIL | 见 §1.4；`--allow-handmade-tables` 才可放行 |

### 1.1 G3 的细节（最容易搞错）

- **`\hbox` > 8pt 才失败**：中文排版里 1–2pt 的 Overfull 是常态，不值得阻塞交付。
- **`\vbox` > 120pt 才失败**：`\vbox` 的 Overfull 常来自浮动体位置，阈值宽松得多。
- **必须全量取 max**：`head -20` 会**漏掉最大值**——曾经因此把有问题的稿子判为 PASS。
- 阈值来源：28 篇基准论文全库收口时，OVF_H 最大值为 **6.9pt**（#19），阈值 8pt 留有余量。

### 1.2 G8 的细节（血的教训）

**日志抓取失败被静默当成「0 个 Overfull」→ 门控形同虚设。**

必备措施：
```
① 抓取失败 → 明确判 gate-log-unreadable（FAIL），不 fallback 到 0
② 用哨兵区分「grep 无匹配」与「链路失败」：先 echo __SSHOK__，再跑 grep
   （否则"没有 Overfull"会被误判为失败）
③ 门控命令内层用**单引号**：shell=True 下双引号被 cmd.exe 吞掉
   → 曾造成**假 MISS=210、OVF 恒 0**
```

### 1.3 G9 的细节：**只查编译当天**，不查「任何日期」

**现象**：交付件标题块出现 `October 14, 2026`，即**编译当天日期**。
它既不是论文信息（不是收稿日/出版日），也不是译者信息 —— 属**环境泄漏**，
使「同一源文件 → 同一交付件」这一性质失效。

**根因**：`\maketitle` 在**未给 `\date`** 时默认用 `\today`。

**修法**：
- 模板**必须**写 `\date{}`（`runpaper.py` 三个模板分支都已写，见 `build_template`）。
- 论文自身的出版日期应进**信息行**（`meta['info']`），不是标题块日期。

**判据为什么不能写成「交付件不含任何日期」**：
论文本身就含日期（收稿年、会议日期、`October 2021`），那样几乎每篇都会 FAIL。
**当天日期只可能来自编译机的时钟**，所以「只查当天」是环境泄漏的**充分判据**。

**检查形态**（`runpaper.py::gate_build_date` / `verify_delivery.py::build_date_patterns`）：
```
October 14, 2026   14 October 2026   Oct. 14, 2026
2026-10-14         2026/10/14        14-10-2026
```
> 测试时可用 `verify_delivery.py --today YYYY-MM-DD` 覆盖「当天」。

### 1.4 G10 的细节：手写表**不都是错的**（真实事故）

**现象**：罗马/阿拉伯表号不归一化，使 **7 张矢量表静默退回手写**，
管线只打印 `NOTE: 仍有手排 tabularx 残留` 却**仍报 7/7 成功并出稿**。

**判据必须**分两类**（这是本门控的核心）**：

| 情况 | 判据 | 处置 |
|---|---|---|
| 该表号在 `tables.json` 里有 **`ok` 记录**，却没走矢量嵌入 | 矢量复刻件**存在却没用上** | **FAIL**（`handmade-despite-ok`） |
| `tables.json` 里**根本没有**该表号 | 原件本来就无法复刻（如 DESIRE6G 的 3 张 `no-rules`） | **允许手写**，打印 INFO |

> 把「有手写表」一律判失败是**错的**——会误伤上述第二类。

**两条独立判据（互相兜底）**：
```
7b  prep.py 打印 HANDMADE_DESPITE_OK= / HANDMADE_NO_RECORD= ，runpaper 解析后判定
    · 解析不到该行 + body.tex 里还有 tabularx → 判 handmade-classification-unreadable
      （**不得静默放行**，同 G8 的教训）
7c  **独立复核**：tables.json 里 status==ok 且有 file 的记录数
    vs body.tex 里实际嵌入的表格图数；不足即 FAIL
```
7c 存在的理由：7b 依赖 prep 的 stdout 格式，**格式一变门控就失效**。
所以再用一条**与 7b 口径不同**的计数（同 §2.2「换抽取口径复核」的思路）。

**放行开关**：`--allow-handmade-tables`。仅在**已确认原件该表确实无法复刻**时使用，
且须在台账「备注」列留违规记录。

## 2. 门控两处经典假阳性（放宽判据前必读）

### 2.1 `tables_pdf` 只认纯数字
- **现象**：#27 的 `2.1-1`/`D.8.3-1` 全数不到（38 张报 **0**）。
- **根因**：表号正则 `表\s*(\d+)\s*（Table` 只接受纯数字。
- **修法**：改 `([0-9A-Za-z][0-9A-Za-z.\-]*)` → #27 报 **34**、#20 报 20。

### 2.2 图号闭合被水印假阳
- **现象**：#27 报 `fig-closure-missing`。
- **根因**：远端 `pdftotext -layout` 把 OMA 水印与图题**交错**，`图` 与 `C.3.1.1-1.` 被拆到两行。
- **关键发现**：**同一个 PDF 用本地 PyMuPDF 抽取时图题完整无损**。
- **修法**：**门控优先用本地 PyMuPDF 重抽文本层**。
- **教训**：**放宽正则前先查"是不是抽取口径不同"**。
  第一版放宽后误计成 40/20，收紧为「只接受期望图号集合内的编号」才对。

> **同一 PDF 不同抽取器结果可能差异巨大**（`pdftotext -layout` vs PyMuPDF 在双栏/水印文档上表现悬殊）。
> 门控应**选可靠的那个**，而非放宽判据。

## 3. 越栏（Overfull）失败定位

### 3.1 三步定位

```
① 读日志取最大值与上下文：
     grep 'Overfull \\hbox' .work/<NN>/main.log        → 全量，不要 head -20
     找到最大那条 → 看它在 .tex 里的位置
② 判断是「列宽」还是「断行」：
     某列宽 < 该列最长单词宽 ？
       是 → 加 \allowbreak 在数学上无解
            → 改列宽/列数/字号/全宽
       否 → 可加断行机会（\allowbreak、\RaggedRight + 连字）
③ 仍不过 → 渲染该页目视，别继续猜
```

### 3.2 已知手法与效果（实测）

| 手法 | 适用 | 实测效果 |
|---|---|---|
| X 列 `>{\raggedright\arraybackslash}X` → `>{\RaggedRight\arraybackslash}X` | 手排表 | 允许词内断行 |
| `\AtBeginEnvironment{table}{...}` + `\sloppy\hyphenpenalty=50\exhyphenpenalty=50` | 所有表格 | #02 12.3 → **0.0** |
| 宽表升级 `table*` + `\textwidth` + `\scriptsize` | 列多/长 token | #05 18.9 → **0.0**、#06 19.2 → **0.0** |
| 自然宽 `tabular` → 改 X 撑满 | 多列中文表 | #22 23.8 → **0.0** |
| 长标识符表升级全宽 + `\scriptsize` | 无空格长 token | #27 47.7 → **4.3** |
| `fvextra` + `breaklines,breakanywhere` | verbatim 算法块 | 121pt → 收敛 |
| `\parbox[t]{\columnwidth}` | 双栏作者块 | 531 → **1.0** |

### 3.3 无效的手法（别浪费时间）

- **对矢量复刻表**做任何排版调整 → 违反保真原则（R-T1），且通常无效（表是图片）。
- **在已经比列还宽的单词里插断点** → 数学上无解，残留 17.0pt。
- **反复调阈值** → 如果全库同方向同比例超差，那是**系统偏差（单位错）**，不是阈值问题。

## 4. 编号闭合口径

```
期望集合 E = figs.json / tables.json 的编号（归一化后）
实际集合 A = 交付 PDF 文本层抽取到的编号（归一化后）
PASS  ⟺  E ⊆ A
```

- **子集判定**，不是相等：正文交叉引用（「如图 3 所示」）会额外产生匹配。
- 两侧**归一化口径必须一致**（罗马数字、`.-` 连字符、全角/半角冒号）。
- OMA 的 md 写作 `表 2.1.-1` 而 `norm()` 输出 `2.1-1` → **探针直接拿 md 原文当 expect 会对不上**，
  把已提取的表误报 MISSING。**探针口径必须与流水线同步**。

### 4.1 「只接受期望图号集合内的编号」

放宽正则时曾把 20 张误计成 40。正确做法：
**先抽出全部候选编号，再与期望集合取交**，而不是把正则放到最宽然后直接计数。

## 5. 译者痕迹（G5）口径

交付 PDF 文本层必须**完全不含**：

| 类别 | 例 |
|---|---|
| 题头元信息表 | 「译文信息」表、含「源文件 / pdftotext」行 |
| 翻译说明 | 整节（含其下 `###` 子节） |
| 篇末自查 | 自查清单整块 |
| 行内译注 | `〔译注：…〕`、`（详见…翻译说明…）` |
| 进度标记 | `[x]`、`TODO`、分隔线 |

**必须保留**（属论文自身元信息）：
中文题 + 英文原题 + 作者/单位/联系/DOI/收稿日期/出处 + 摘要 + 关键词。

### 5.1 剥离按**标题层级整块删**

- 自查/译注汇总类**按标题层级整块删**（曾因只删正文行，导致 `###` 子节泄漏）。
- 元信息字段内的 `〔译注〕` 在字段取值处剥离。
- 悬空引用（「其统一译法见『翻译说明』第 5 条。」）也要删。
- 裸行标记、分隔线一并处理。

### 5.2 ⚠️ 译注**可以**留在工作用 md

实测 **28/28 篇 md 全部含 `〔译注…〕`，共 487 条**——
这是**翻译方法论的一部分**（记录取舍，如「Table 9 疑为 Table 7 之笔误」），**不是残留**。

- **交付 PDF** 必须干净。
- **md 是工作源**，译注属**审计线索**，应当保留。
- **只清一篇会造成全库不一致，比不清更糟。**

## 6. 门控 PASS ≠ 正确：目视抽验

**必须目视抽验的对象**：

| 对象 | 为什么机器查不出来 |
|---|---|
| 表区内容 | `status == ok` 但导出的是正文段落/另一张表/折线图（实测 5 例） |
| 图与图题配对 | 配对错误时张数、尺寸、md5 **全都正常** |
| 版式 | 栏数错了不影响任何数值门控 |
| 页面几何 | ±3pt 舍入需人眼确认是舍入而非系统性偏差 |
| 译者痕迹 | 非标准措辞可能逃过关键词匹配 |

**抽验方式**：把全部图/表渲染成**联系表**，与原件并排对读。
#20 v2 的抽验记录（图 1/3/4/5/6/7/8/9/18/19/20 与图题全部配对正确）就是本步骤的验收标准格式。

## 7. 失败定位手册（按日志关键字）

| 日志关键字 | 根因 | 修法 |
|---|---|---|
| `! Missing $ inserted` | 数学符号未进数学模式 | 希腊字母/算符用 `\ensuremath{}` 包；补 MATHMAP |
| `! Misplaced alignment tab character` | 文本里 `&` 未转义 | 转义 `\&`（表题、元信息行尤其常见） |
| `! Extra alignment tab` | 表格列数与列格式不符 | 全表最大列数 + 全行补齐/截断 |
| `! Undefined control sequence` | 宏未定义；或反斜杠被吞 | 检查 `\f`/`\x` 类伪转义；确认宏包已载入 |
| `! LaTeX Error: longtable not in 1-column mode` | 双栏下用 `longtable` | 所有 pipe 表（含引用块内 `> \|`）转 `tabularx` |
| `Shaded / Highlighting / NormalTok undefined` | pandoc 代码高亮 | pandoc 加 `--no-highlight` |
| `Missing character: There is no X` | 字体缺字形 | 加 `newunicodechar` 回退映射（见 §7.2） |
| `Overfull \hbox ... too wide` | 见 §3 | 见 §3 |
| `Overfull \vbox ... too high` | 浮动体位置 | >120pt 才失败 |
| `package inputenc Error` / BOM 相关 | **UTF-8 BOM** 进了源文件 | 写文件不带 BOM；脚本 ASCII |
| 页面尺寸不对 | **`pt` 而非 `bp`** | 全库检查 geometry 单位 |
| `gate-log-unreadable` | 日志链路失败 | 修抓取链路，**不要**默认 0 |
| 产出为 `-new.pdf` | 目标文件被占用（Acrobat 锁） | 请用户关闭后替换 |

### 7.1 反斜杠层级惨痛教训
Python 源码里写 `'\alpha'` 是**合法**转义？不——`\a` 是 BEL、`\b` 是 BS、`\t` 是 TAB、`\f` 是 FF、`\x` 是十六进制前缀。
这些会被**静默**转成控制字符，**不报错**。

- 注入 LaTeX 命令必须保证源文件里是 **2 个反斜杠**（Python 值 1 个反斜杠 → 输出直通）。
- **批量字符串注入务必用「编辑器写脚本文件」而非 shell 内联**。
- 注入后**必须整行校验控制字符**（`ord(c) < 32` 计数为 0；内部哨兵字符除外）。

## 7.2 内建字形回退表（G2 的正解）

`runpaper.py` 有一张内建 **`GLYPH_FALLBACKS`** 表（U+XXXX → LaTeX 替换），
由 `_glyph_block()` 展开成 `\newunicodechar{...}{...}` 注入导言区。
**字体缺字形时不要一篇篇手加**——补进这张表即可全库生效。

**为什么必须有这张表**：字体（serif/CJK/mono）对大量数学/Greek/算符码位没有字形。
XeLaTeX **不报错**，只**印不出东西**并在日志写 `Missing character`，正是 G2 计数的东西。

**实测缺口（S2，IEEE WSN 论文）**：`MISS=52`，其中
`U+2032 PRIME` **38 次**，另有 `α`(U+03B1)、`λ`(U+03BB)、`≠`(U+2260)。

**`\prime` 的坑（必须记住）**：
`\prime` **不能**在文本模式直接用（`Missing $ inserted`）。
必须包 `\ensuremath{}`：
```latex
\newunicodechar{′}{\ensuremath{\prime}}
```
实测（S2）：`B′` 渲染成正确的**上标 prime**，且文本层**仍能抽出 U+2032**（77 处）。
> 若写成 `\ensuremath{^\prime}` 会把位置再抬一层，与上下文（如 `12′`）不一致。

**表的内容**：除原有算符表外，另补希腊小写/大写、关系符、箭头、集合符、
`′`/`″`、破折号、省略号等，共 90 条（**去重后**，同一码位后写者胜出）。

**源码纪律（极重要）**：
表里每个码位都写成 **`\uXXXX` 转义**（用 `chr()` 展开），
**不得**在 `.py` 里直接写字形 —— 本仓库已因 PowerShell 往返非 ASCII `.py`
**翻车两次**（中文变 mojibake **并吞掉下一行代码**）。改完必跑：
```
python scripts/_audit_mojibake.py            # OK: no comment-swallowed-code damage
python scripts/_audit_mojibake_literals.py   # 合计可疑行: 0
```

## 8. 回归纪律

**改脚本必跑回归用例集**（至少覆盖四类）：

| 用例类型 | 代表特征 |
|---|---|
| 侧栏图题 | Springer/JKSU（图题在图左侧窄栏） |
| 矢量多子图 | Access 类 |
| 无框线表 | MDPI Sensors 类 |
| 长标识符表 | 含 >14 字符无空格 token |

**改动收益/风险判断**：
> 当**改动收益是纯观感、而失败模式是回归**时，**回到已验证状态**是正确决策，不是放弃。
> 先量化收益/风险，再决定是否继续调参。
> （实例：双栏作者块通栏试了 4 轮，每轮引入新问题；收益是纯观感，代价 1.00002pt vs 阈值 8pt → 止损。）

**提交纪律**：提交必须**显式列文件**，不要 `git add` 目录（曾误把未验证的改动一起提交）。
