# 表格矢量复刻规则（tables）

> 用户指令：「有些表怎么是被你手动写出来的，非常丑！你就不能找个办法复刻一下」
> → **表格优先从原件矢量复刻**；只有原件中无法定位的表才退回手排。

## 0. 首要原则

**绝不手写 LaTeX 表来"近似"原表。** 原件里的表是矢量对象（线、文字、单元格框），直接抽取嵌入才是「复刻」。
手排必然引入**丢行 / 错位 / 观感差**三类问题（生产实测全部实际发生过）。

---

## 1. 三态判定（**不是二态**）

⚠️ **「文件存在」≠「有矢量表」**：`tables.json` 可能是空对象 `{}`（跑过提取但一张都没提出）。
按二态规则会把这类篇目**误保护**，导致越栏修不了。

| 状态 | 判定 | 允许的操作 |
|---|---|---|
| `tables.json` **不存在**，或 **`entries == 0`** | **无矢量表** → 该篇表格全是手排 | 可用排版手段修越栏/列宽/字号 |
| `entries > 0` 且该表号 `status == ok` | **矢量复刻表** | **禁止**改字号/列宽/列型（保真优先） |
| `entries > 0` 但该表号 `status != ok` | 提取失败 | 需人工判断，**不得默认当手排处理** |

实测：曾出现空 `{}` 的篇目有 #07/#08/#09/#12/#14/#19/#20/#22；#27 有 38 张矢量表。

### 1.1 两类表对照

| | **矢量复刻表** | **手排表（tabularx）** |
|---|---|---|
| 生成方式 | 用 `page.show_pdf_page()` 从原件抽出表区 → 单页矢量 PDF；LaTeX 侧 `\includegraphics` 嵌入 | md 的 pipe 表转 `tabularx` |
| 表内文字 | **保留英文原文**（用户已确认「我没打算全译」） | 中文（译文内容） |
| 表题 | **中文**（`\captionsetup{labelformat=empty}` 避免重复编号） | 中文 |
| 保真度 | 与原件**逐像素同版式**（无限缩放不糊，单表约 30 KB） | 近似 |

## 2. 硬性规则

### R-T1 矢量复刻表**不得**被排版规则改动
**禁止**对矢量表改：字号（`\scriptsize`/`\footnotesize`）、列宽、列型、`\RaggedRight`、断行规则、`table`/`table*` 之外的宽度设定。

理由：矢量表的价值就是**与原件逐像素同版式**；任何排版调整都等于回到"手写近似"。

代码约束：命中 `tabimg(no)` 时**立即 return**，宽表升级 / `col_specs` / `\RaggedRight` 等规则**只作用于其后的手排分支与兜底分支**。
**改代码时不要把这个提前 return 挪到后面。**

### R-T2 手排表可用排版手段修越栏
允许：`>{\RaggedRight\arraybackslash}X`（配合连字允许词内断行）、`\sloppy\hyphenpenalty=50\exhyphenpenalty=50`（在 `table`/`table*` 环境内）、宽表升级 `table*`+`\textwidth`+`\scriptsize`、按内容推断列型。

### R-T3 越栏根因先判「列宽」还是「断行」
若某列宽度 **<** 该列最长单词宽度，则**插 `\allowbreak` 在数学上不可能解决**。

> 实测（受控实验，证据确凿）：#02 表 III/IV/V 为 6 个 X 列，`\columnwidth` = 236.85pt → 每列约 **39.5pt**，
> 而 `Exponential-Rayleigh` 单字 **45–60pt**——**单词本身比整列宽**。
> 加断行机会后仍残留 **17.0pt**。

此时应改**列宽 / 列数 / 字号 / 全宽**，而不是继续加断点。

## 3. 区域定位算法

> **2026-10-14 重写**：旧算法（「取框线更多的一侧」+ 不分栏 band）存在**取错区域**的隐性错误——
> `status` 照样是 `ok`，但导出的可能是**正文段落**或**另一张表**。详见 §5。

### 3.1 主算法（extract_tables.py）

**第 1 步：合并逻辑框线**（`_merge_rules`）
同一 y（容差 2pt）且 x 相邻（间隙 ≤6pt）的分段框线并为一条。

> 上限 6pt 是**有意的**：p22 的 `y=710.6` 左右栏各有一条 `x 51-289.1` 与 `x 306.2-544.3`，
> 正是靠这条间隙不被误并，才保住分栏。

**第 2 步：判定表题**（`caption_like`，按优先级）——先排除"像正文句"的候选：

1. `prev_gap`（与**同栏**上一文本行的行距）**< 5pt 且整行 >55 字符** → **硬**否决（嵌在段落里的交叉引用）
   ⚠ 不能只用行距：OMA 规范的表题也紧贴上文（gap≈0），单独用会**整篇误杀**
2. 编号后紧跟小写词且整行较长 → 像正文句
3. 编号后紧跟动词（shows/lists/outlines/reports/…）且整行较长 → 像正文句
4. 编号后紧跟句点再接大写词且整行较长 → 像正文句
   （⚠ 分隔符类正则会吃掉编号后的 `.`，**句点要从 `after` 里看，不能查 `m.group(0)`**）
5. 形如 `标题短语 + )。再接完整句子` → 像正文句（OMA `Table: 6.4.3.-2 … (…). The response includes …`）
6. 整行 >90 字符且以句末标点收尾 → 像正文句

命中 2–6 **不是**一票否决，还须 `_has_adjacent_rules()` 同时成立才算真表题——
否则会误杀 `TABLE I. Power and energy consumption …` 这类「句点 + 名词短语」的真表题。

`_has_adjacent_rules` 要求框线：① 与表题**同栏** ② **离本表题比离其他表题更近**。

> ⚠ **不要恢复**旧的 `^(summar|shows|…)` 守卫。真表题也叫 "Summary of the fitted …"，#20 Table 13/15 就是这么丢的。

**第 3 步：定区域**（`cluster_region`）

1. 采集页面框线（`get_drawings()`；高 <1.5pt 且宽 >30pt 为横线）
2. band 只由**同栏**相邻表题界定（`_same_col`，以页面中线分左右栏；**中线 ±6% 视为"骑中线"，与两侧都兼容**）
3. 取**离表题最近**的一侧为表体纵向范围（**不是**框线更多的一侧）
4. 只收集与首条框线**同宽度**（`_same_width`）且与当前簇相邻（间隔 ≤ `step_gap`）的框线
5. 横向取该范围内的垂直线（无则取横线端点）
6. 裁掉页眉页脚（`|y| < 48pt`）；**导出区域不含表题**（表题由 LaTeX 渲染中文）；若表题与表区相交，按表题 y 裁掉

### 3.2 无框线兜底（`fallback_region`）

对全无框线的期刊表（如 #19 整页 `drawings=0`）：
**视觉行（y 重叠）聚类 + 多单元格（同级多段）判据**。

> 列起始法**不够**——#19 曾 0/7，改用视觉行 + 多单元格后 **7/7**；#09 3/3。全库再无 `no-rules`。

## 4. 表号归一化与表题体例

原件 `Table: 3.2.-1` → md `表 3.2-1`；`TABLE III` → `3`（罗马数字转阿拉伯）。

| 体例 | 示例 | 出处 |
|---|---|---|
| OMA 式（冒号 + 点连字符） | `Table: 7.3.-4` | #27 |
| 期刊式（无冒号） | `Table 1` / `Table 10` | #20 等 |
| 罗马数字（常见全大写） | `TABLE I` / `TABLE III` / `Table V` | #02 #05 #19 #22 等 |
| 缩写式 | `Tab. 2` | 少数 |
| 附录式（字母开头） | `Table: C.3.1.1-1` | #27 附录 |

### 4.1 ⚠️ 踩过的坑（**最重要的一条**）

最初正则**写死 `Table:\s*`（要求冒号）** → **期刊论文全部提取不到表**（#02/#05/#19/#22 全为 0，
全库仅 **22/111** 张）。

放宽为 `(?:TABLE|Table|Tab\.?)` + 允许无冒号 + 罗马数字 + 连续分隔符 `.-` 后，
全库提取率 **22 → 87 / 111（20% → 78%）**；再修 `status==ok` 区域错误后达 **111/111（100%）**。

> **凡「某功能全库无效」，先怀疑最窄的那个正则/判据。**

### 4.2 比对口径必须同口径

- `--expect` 传入的罗马数字（md 写作 `表 I`）**必须与 `norm()` 同口径归一化**，否则比对全不中。
- OMA 的 md 写作 `表 2.1.-1`，而 `norm()` 输出 `2.1-1`——探针直接拿 md 原文当 `--expect` 会对不上，
  把已提取的 4 张表**误报为 MISSING**（显示的 107/111 是**探针口径问题**，真实是 111/111）。

## 5. `status == ok` ≠ 区域正确（**验收必读**）

旧算法下多张表的 `status` 均为 `ok`，但导出的是**正文段落**或**另一张表**。已确认根因：

| 现象 | 根因 |
|---|---|
| 表 A 与表 B 导出内容**完全相同** | band 上界取到同页另一张表的表题；上方框线比下方长 → 按「取更长一侧」选中了上一张表 |
| 某表只剩 16pt | band 下界取到**右栏**表的表题 → 左栏表体被截断 |
| 某表高 563pt 吞到页尾 | 同栏无中间表题，band 无上界，一路吃到下一张表的框线 |
| 导出 55×65 **空白** | 该表每行框线被画成**每单元格一段**；`_same_width` 以最左一格（48.7pt）为基准，整行框线（49.8–297.1）宽度不符 → 全落选，区域只剩第一列 |
| 导出 **折线图**（图不是表！） | 末段用**竖线**微调横向范围时没做同栏判断：表体在右栏，但左栏图的竖线与表体 y 区间重叠 → 横向被拉到左栏 |
| 整张 `no-rules` | `_same_col` 严格按中线归类，**居中表题**（骑在中线上）判成左栏、全宽表体判成右栏 → 不匹配。**修法：中线 ±6% 视为"骑中线"** |
| 导出 **折线图**（第二种） | 该侧首个框线只是**部分分段**（同行两段中间有 32pt 空档，超出 6pt 合并容差）→ 簇只有 1 条框线被丢弃。**修法：退化时改用该侧 y 相邻行框线的并集** |
| 表只框住 59–95pt 宽标签列 | 「窄标签列 + 全宽正文列」两段，合并后必然跨中线。**不要**为此加"跨中线就不合并"的保护，否则退化成只取标签列 |
| **表头整行被横切一半**（区域纵向不足） | booktabs 体例取到 **midrule** 而非 toprule；且表题在**左侧边距**时 `cap_rect.y1` 不是硬顶。详见 §5.2 |

### 5.1 验收口径（**四条**，缺一不可）

```
✓ tables.json 全表 MISSING == []
✓ 无 w < 60 or h < 25 的 TINY 区域
✓ CLIPPED-TOP == []        （区域纵向不足、首行/表头被裁；渲染量首次着墨 y）
✓ 对新增/修复的表**目视复核**（渲染成联系表看内容是否真是那张表）
```

> **只数「提取成功张数」会把区域错误全部漏掉。** 实测 5 个"`status==ok` 但区域错误"的 bug，
> 都是靠目视联系表发现的。

### 5.2 第四条口径：`CLIPPED-TOP`（区域**纵向不足**）

**前三条全查不出这一类**：区域确实"框住了那张表"，`status=ok`、`MISSING=[]`、
尺寸也远大于 TINY —— 但上边界落在**表头行中间**，表头只剩字的下半截。

| 样本 | 表头行 y 区间 | 区域 top | 结果 |
|---|---|---|---|
| `#Agu T1` | 602.20..610.67 | 608.10 | 横切一半 |
| `#Agu T15` | 64.15..72.62 | 75.50 | 整行在区域**之上** |
| `#Agu T16` | 210.95..219.42 | 222.30 | 整行在区域**之上** |

实测 `#Agu` 20 张里 **10 张**中招（`tables.json` 里 `status` 全是 `ok`）。

**判据**（`extract_tables.py::detect_clip_top`）：渲染 crop 顶部条带，
量首次着墨 y。三个条件**同时**成立才判 `CLIPPED-TOP`：

1. `ink_top < 1.0pt` —— 内容贴着裁切边上沿
2. `band_h > 1.6pt` —— 该条带**比一条框线厚**
3. `coverage < 0.90` —— 它不是一条满宽细线

(2)(3) 是**必需**的，否则会大量误报：grid 体例的表本来就有一条**贴边上沿的满宽细框线**
（实测 `#OMA` 38 张里 32 张如此，`b0_y0=0.00, band_h=0.75, coverage=0.038`），
那是正常版面，不是被切。另外还会跳过 `coverage < 0.02` 的杂点（`show_pdf_page`
把邻栏抗锯齿鬼影一并带进来，实测 `#Agu T11/T12/T13` 上沿有 2–8px、覆盖率 0.2%~0.8% 的碎点）。

输出：`tables.json` 每张表多两个字段 —— `clip_top: bool` 与 `clip_info: {ink_top, band_h, coverage}`；
门控行 `SUMMARY ... CLIPTOP=<n>`，`CLIPTOP>0` 时脚本**以退出码 1 结束**并在 `NEXT:` 里点名。

**修法**（`_toprule_above` + `_expand_top_for_header` + `cluster_region` 三处）：

- 识别 booktabs **toprule**：取 `top` 之上**最近**的一条框线，且其横向跨度
  ≥ 70% 表宽（不搜更远的：实测会取到通栏页眉线 y=45.9 而不是真 toprule y=598.4）。
- 表头行**横跨** toprule（rule 落在字形中段）时，`r.y1 <= top+1` 会整行漏掉 →
  放宽为「仅当找到 toprule 时」额外收 `r.y0 <= toprule <= r.y1` 的行。
- 表题在**左侧边距**（与表体 x 不相交）时，`cap_rect.y1` 会落到表头行下方 →
  不能用它当硬顶；且 `cluster_region` 末尾「表题落在区域内就裁掉」的钳制也必须跳过，
  否则上边界被压到 `cap_rect.y1+2`，正好落在表头行中间。
- `_same_col` 对左边距表题会**偶然**命中远处另一张表的框线（`#Agu T15/T16`
  命中 y=345.7 x=141.7..453.7），使真正的 toprule/midrule 一条都进不了 seed →
  当「同栏判据选出的最近框线**比 base 里最近的更远**」时，改取**最宽一族**框线。

**回归证据**（经 8 条用例与全库基准验证）：`#Agu` 修前
`CLIPPED-TOP=10`（全部 `ink_top=0.0`）→ 修后 `0`；`#OMA` 38 张、`#Lee` 7 张、
`#Du` 12 张、`#Mohammed` 4 张**零误报**；28 篇原件扫描张数**无一篇减少**、无新增
missing/norules。

## 6. 手排分支（只在提取不可行时使用）

> ### ⚠️ 6.0 手排是**被判据约束**的，不是「提示一下」
>
> **判据分两类（G10）**：
>
> | 情况 | 含义 | 处置 |
> |---|---|---|
> | 表号在 `tables.json` 里有 **`ok` 记录**，却走了手排 | 矢量复刻件**存在却没用上**（表号归一化 / 表体跳过有缺陷） | **门控失败** `handmade-despite-ok` |
> | `tables.json` 里**根本没有**该表号 | 原件该表**本就无法复刻**（如 DESIRE6G 的 3 张 `no-rules`） | **允许手排**，只打印 INFO |
>
> **务必分清**：把第二类也判失败是错的（会误伤合法手排）；
> 只发提示则是**真实事故**的成因——罗马/阿拉伯表号不归一化使 7 张矢量表
> **静默退回手排**，管线却仍报 7/7 成功并出稿。
>
> 仅当**已确认原件该表无法复刻**时，才可显式 `runpaper.py --allow-handmade-tables`；
> 该开关会在运行摘要里留违规记录（对应台账「备注」列应写 `DEVIATION`）。
>
> 代码落地见 `references/gates.md` §1.4（判据 7b 解析 + 7c 独立复核）。

### 6.1 表格内容准备

- 表格列数改「**全表最大列数 + 全行补齐**」（保内容，不丢列）。
- **`cells[2:]` 是错的**：它假设第 2 行是分隔行 → 遇「无分隔行的表」直接**丢掉首行数据**
  （#27 缩略语表丢 CID 行）。改为按内容识别表头/分隔行。
- 行内列数与表头不一致时补齐或截断（修 `Extra alignment tab`）。

### 6.2 排版手段

- 列宽：**≥4 列全 X 列**（大幅降 Overfull）；三列表格亦全 X。
- 宽表：估算超可用宽度 → 升级 `table*` + `\textwidth` + `\scriptsize`。
- 长标识符表（含 `bad_certificate_status_response` 等 >14 字符无空格 token）→ 升级 `table*` + `\scriptsize`
  （实测越栏 **47.7 → 4.3pt**）。
- 表内文本：先转义特殊字符（`& % $ # _ { }`，以及 `^ ~`）再做数学化。
- `<br>` → `\newline`。

### 6.3 非表格的内容

- **ASCII 线框图不是表** → 保持代码围栏/verbatim。转 tabularx 必然错位。
- **表题中的 `&` 必须转义**（否则 `Misplaced alignment tab character`）。
- 表格区域误把**原件英文表题**截进图里 → 必须在导出前裁掉。

### 6.4 表体跳过逻辑

命中矢量表后，跳过 md 中该表的**全部**交错表体（pipe 行 / 代码围栏可交替多块，直到新内容）。
**只跳第一块会残留孤儿 `tabularx`。**

## 7. 调试工具链

```
python scripts/extract_tables.py <orig.pdf> <outdir> --expect "1,2,3"
python .../_tf_final.py                     全库终验（归一化表号）
python .../_tf_visall.py                    把全部表渲染成联系表，**目视复核**
python .../_tf_trace2.py <orig.pdf> <pno>   逐行显示表题判定与原因
python .../_tf_gap.py    <orig.pdf> <pno>   显示每行 prev_gap
python .../_tf_merge.py  <orig.pdf> <pno>   显示该页合并后的逻辑框线
python .../_tf_side.py   <orig.pdf> <pno>   显示每张表题上/下侧的 gap 与框线数
python .../_tf_p13.py    <orig.pdf> <pno>   端到端打印表题判定 + 最终区域
python .../_tf_page.py   <orig.pdf> <pno>   转储该页框线 + 文本行 bbox
python .../_tf_miss.py   <NN...>            逐篇报告 MISSING 与 TINY 区域
```

**上传表格 PDF 要用显式文件列表**：`cmd.exe` 不展开本地通配符，`scp "tables/tab_*.pdf"` 会**静默失败**。
